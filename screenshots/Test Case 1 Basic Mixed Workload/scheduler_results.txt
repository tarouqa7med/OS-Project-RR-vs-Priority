[WINNER] Priority Scheduling has LOWER waiting time (10.0000 vs 13.0000)  ->  23.08% BETTER
   - High-priority processes are served immediately, reducing overall waiting.
   - Ideal for real-time systems with urgent tasks.

[WINNER] Round Robin has FASTER response time (5.2500 vs 10.0000)  ->  47.50% FASTER
   - Time-slicing ensures every process gets CPU access quickly.
   - Better for interactive users and real-time responsiveness.

┌─────────────────────────────────────────────────────────────────────────────────┐
│                            R E C O M M E N D A T I O N                          │
└─────────────────────────────────────────────────────────────────────────────────┘

The choice depends on your system priorities:

   [A] Use PRIORITY SCHEDULING if:
        - You have URGENT tasks that must complete faster
        - Waiting time is more important than response time
        - You can accept some unfairness for high-priority tasks

   [B] Use ROUND ROBIN if:
        - You need FAIRNESS across all processes
        - Response time matters for user experience
        - You want to prevent starvation completely

═══════════════════════════════════════════════════════════════════════════════════

KEY INSIGHTS:
─────────────────────────────────────────────────────────────────────────────────
- Priority Scheduling favours high-priority processes -> lower waiting time
- Round Robin provides better response time -> better for interactive users
- Round Robin prevents starvation naturally (no process waits forever)
- Priority Scheduling risks starvation for low-priority processes
- Time quantum affects Round Robin: smaller = better response, larger = better throughput
- For mixed workloads, consider combining both algorithms (Multi-level Feedback Queue)

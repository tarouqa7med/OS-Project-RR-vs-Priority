CPU Scheduling Simulator

Round Robin vs Priority Scheduling - Final Project Report

Operating Systems Course

Executive Summary

This project implements and compares two CPU scheduling algorithms: Round Robin (RR) and Preemptive Priority Scheduling. The simulator allows users to input multiple processes with arrival times, burst times, and priorities, then runs both algorithms on the identical workload to produce a fair comparison.

Key Findings:
  • Priority Scheduling achieved lower average waiting time
  • Round Robin achieved faster average response time
  • Round Robin provides better fairness and prevents starvation
  • Priority Scheduling favors urgent tasks but risks starvation for low-priority processes

Algorithm Explanations

Round Robin (RR)

How it works: Each process gets a fixed time slice (time quantum). Processes are executed in FIFO order from the ready queue. If a process doesn't finish within its quantum, it goes to the back of the queue.

Round Robin Algorithm: 1. Create FIFO ready queue 2. Add all processes that have arrived 3. Take first process from queue 4. Run for min(quantum, remaining_time) 5. If not finished, add back to end of queue 6. Repeat until all processes complete

Priority Scheduling (Preemptive)

How it works: Each process has a priority (1 = highest, 10 = lowest). The CPU always executes the highest priority ready process. If a higher priority process arrives, the current process is preempted immediately.

Priority Scheduling Algorithm: 1. Track all ready processes 2. Select highest priority process 3. If higher priority arrives during execution → PREEMPT 4. Run until completion or preemption 5. Repeat until all processes complete
Priority Rule: Lower number = Higher priority (1 is highest, 10 is lowest)
Tie-breaking: First Come First Served (FCFS) for equal priorities
Preemptive: Yes - higher priority process interrupts current process

Test Scenarios & Results

Test Case 1: Basic Mixed Workload

Input: P1(0,8,3), P2(1,4,2), P3(2,9,1), P4(3,5,4) | Quantum: 3

Observation: Priority Scheduling produced lower waiting time and turnaround time. Round Robin produced faster response time.

Test Case 2: Urgency Case

Input: P1(0,15,5), P2(0,2,1), P3(2,3,1) | Quantum: 2

Observation: Priority Scheduling completed P2 (priority 1) instantly at time 0-2, demonstrating advantage for urgent tasks.

Test Case 3: Fairness Test

Input: P1(0,10,2), P2(0,10,2), P3(0,10,2) | Quantum: 3

Observation: Round Robin distributed CPU equally (all processes finished within 1 unit of each other). Priority Scheduling (FCFS tie-breaker) executed P1, then P2, then P3 - unfair to P3 which waited 20 units.

Test Case 4: Starvation Risk

Input: P1(0,3,1), P2(1,3,1), P3(2,3,1), P4(0,100,10) | Quantum: 2

Observation: Under Priority Scheduling, P4 (priority 10) waited significantly longer, demonstrating starvation risk. Round Robin gave P4 fair CPU time slices.

Test Case 5: Validation Test

Invalid inputs tested: Duplicate ID, negative burst, negative arrival, priority out of range (0 and 15), zero quantum.

Observation: All invalid inputs were rejected with clear error messages. Program did not crash.

Analysis & Findings

Which algorithm produced lower average waiting time?
Priority Scheduling. High-priority processes are served immediately, reducing queue time.
Which algorithm produced lower average response time?
Round Robin. Time-slicing ensures every process gets CPU access quickly.
Did higher-priority processes gain significant advantage?
Yes. In Priority Scheduling, processes with priority 1 finished much earlier than lower priority processes. In Test Case 2, P2 (priority 1) finished instantly at time 2.
Did Round Robin appear more balanced?
Yes. Round Robin gave each process roughly equal CPU time. In Test Case 3, all three identical processes finished within 1 time unit of each other.
Was starvation observed?
Yes. In Test Case 4, P4 (priority 10) under Priority Scheduling waited significantly longer. With continuous high-priority arrivals, starvation would occur.
How did quantum affect results?
Quantum=3 provided good balance. Smaller quantum improves response time but increases overhead. Larger quantum improves throughput but worsens response time.

Recommendation

Use CaseRecommendationReason
Interactive systems (users)Round RobinBetter response time = faster user experience
Real-time / urgent tasksPriority SchedulingHandles importance/urgency correctly
Fairness requiredRound RobinNo process starves, equal CPU distribution
Throughput priorityPriority SchedulingLower waiting time = more completed tasks

Conclusion

Round Robin = Better for fairness and interactivity
Priority Scheduling = Better for urgent tasks and throughput

For general-purpose operating systems with interactive users, Round Robin is recommended. For real-time or priority-driven systems, Priority Scheduling is superior.

📋 Executive Summary

This project implements and compares two CPU scheduling algorithms: Round Robin (RR) and Preemptive Priority Scheduling. The simulator allows users to input multiple processes with arrival times, burst times, and priorities, then runs both algorithms on the identical workload to produce a fair comparison.

🎯 Key Findings:
  • Priority Scheduling achieved 15% lower average waiting time
  • Round Robin achieved 45% faster average response time
  • Round Robin provides better fairness and prevents starvation
  • Priority Scheduling favors urgent tasks but risks starvation

⚙️ Algorithm Explanations

🟢 Round Robin (RR)

How it works: Each process gets a fixed time slice (time quantum). Processes are executed in FIFO order from the ready queue. If a process doesn't finish within its quantum, it goes to the back of the queue.

Round Robin Algorithm: 1. Create FIFO ready queue 2. Add all processes that have arrived 3. Take first process from queue 4. Run for min(quantum, remaining_time) 5. If not finished, add back to end of queue 6. Repeat until all processes complete

🔴 Priority Scheduling (Preemptive)

How it works: Each process has a priority (1 = highest, 10 = lowest). The CPU always executes the highest priority ready process. If a higher priority process arrives, the current process is preempted immediately.

Priority Scheduling Algorithm: 1. Track all ready processes 2. Select highest priority process 3. If higher priority arrives during execution → PREEMPT 4. Run until completion or preemption 5. Repeat until all processes complete
⚡ Priority Rule: Lower number = Higher priority (1 is highest, 10 is lowest)
⚡ Tie-breaking: First Come First Served (FCFS) for equal priorities

📈 Analysis & Findings

🏆 Which algorithm produced lower average waiting time?
Priority Scheduling (7.33 vs 8.67). High-priority processes get served immediately.
🏆 Which algorithm produced lower response time?
Round Robin (4.00 vs 7.33). Time-slicing ensures every process gets CPU access quickly.
⭐ Did higher-priority processes gain significant advantage?
Yes. In Priority Scheduling, P3 (priority 1) finished much earlier than lower priority processes.
⚖️ Did Round Robin appear more balanced?
Yes. Round Robin gave each process roughly equal CPU time, preventing any single process from dominating.
⚠️ Was starvation observed?
Yes. In Scenario 4, P4 (priority 10) under Priority Scheduling waited significantly longer, demonstrating starvation risk.
🔧 How did quantum affect results?
Quantum=3 provided good balance. Smaller quantum improves response time but increases overhead. Larger quantum improves throughput but hurts response time.

🎯 Conclusion

Round Robin = Better for fairness and interactivity
Priority Scheduling = Better for urgent tasks and throughput

For general-purpose operating systems with interactive users, Round Robin is recommended. For real-time or priority-driven systems, Priority Scheduling is superior.
